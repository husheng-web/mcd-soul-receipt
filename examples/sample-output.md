## Step 1 · 情绪转译（本地，无工具调用）

**第 1 层 · 接住原话** —— 原样保留，不做书面化翻译：

> 「加班到现在，好累，什么都不想干」

**第 2 层 · 归到情绪簇** —— 命中语料库「簇 1 · 班味 / 打工人」的「又加班到十点」行 → **疲惫·孤独**

**第 3 层 · 命名 + 定调** —— 生成病名与语气：

```json
{
  "original_words": "加班到现在，好累，什么都不想干",
  "emotion": "疲惫·孤独",
  "polarity": "negative",
  "intensity": 8,
  "scene": "加班到十点",
  "diagnosis": "加班型深夜综合症",
  "intent": "补电型",
  "taste_vector": { "fried": 0.8, "sweet": 0.3, "caffeine": 0.9, "spicy": 0.2, "light": 0.1 },
  "tone": "quiet_companion"
}
```

**判断依据**

| 字段 | 依据 |
|---|---|
| `intensity = 8` | 基准 5，「到现在」+1、「什么都不想干」+2 |
| `diagnosis = 加班型深夜综合症` | 按 `emotion-lexicon.md` 第四节规则生成（程度前缀 + 情绪核心 + 医学后缀） |
| `intent = 补电型` | 疲惫·孤独 + 深夜 → 语料库簇 1「又加班到十点」行 |
| `caffeine = 0.9` | `intent = 补电型` 的主导维度，查 `emotion-taste-map.md` |
| `tone = quiet_companion` | negative + 高强度 → 匹配矩阵（**不允许** dry_humor） |
| `scene = 加班到十点` | 具体场景，非泛词 |

**结构决策**

| 位置 | 选品 | 理由 |
|---|---|---|
| 主食 | 板烧鸡腿堡 | 三位最高分。麦辣系虽更「油炸」，但辣属性 1.0 与 `spicy=0.2` 冲突，被匹配度公式自然压下 |
| 小食 | 麦乐鸡5块 | 油炸属性 0.8 **恰好命中** `fried=0.8` 偏好峰值，匹配度 1.0 |
| 饮品 | 小杯鲜萃咖啡 | `caffeine = 0.9 > 0.6` → **硬规则 R2 强制含咖啡因**，且为咖啡因饮品最高分、同档最低价 |

甜品未加入：疲惫场景「必含」为咖啡因饮品，`sweet = 0.3` 未达甜品触发线。

## 为什么这个样例重要

它展示了本 Skill 的三个可验证承诺：

1. **每个数字都有来源**——价格来自 `calculate-price`，营养来自 `list-nutrition-foods`，门店来自 `query-nearby-stores`，本文件的每一个数值都可在 2026-10-14 对同一门店复现
2. **每个决策都有依据**——为什么选板烧而不是麦辣（辣属性冲突被公式压下），为什么必含咖啡因（硬规则 R2），为什么用安静陪伴而不是幽默吐槽（tone 矩阵）
3. **缺口被明确标注而不是掩盖**——麦旋风的营养缺失被写成脚注，这是「宁可少一个数字，不编一个数字」

这三点，是「真实使用 MCP」与「套用模板」的区别。
