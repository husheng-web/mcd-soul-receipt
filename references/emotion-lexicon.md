# 情绪语料库 · Emotion Lexicon

> 本文件是 `SKILL.md` **Step 1（情绪转译）的第一道工序**，优先级高于 `emotion-taste-map.md`。
> 那份文件管「情绪 → 口味」，这份文件管「**人话 → 情绪**」。
>
> **为什么需要它**：年轻人不说「我感到疲惫、委屈、焦虑」。他们说「班味腌入味了」「被导师改崩溃了」「已老实」。
> 如果入口只认书面情绪词，这个 Skill 在真实使用中会有一半的输入接不住——**接不住，就谈不上懂**。

---

## 一、转译三层（Step 1 的执行顺序）

用户的输入不是「情绪」，是**一段有语境的抱怨或感慨**。必须经过三层加工，才能变成可配餐、可命名的素材。

```
第 1 层  接住原话        不做任何替换，先原样保留用户说的那句话
          ↓
第 2 层  归到情绪簇      在语料库里找最接近的簇（可多簇命中，取强度最高者）
          ↓
第 3 层  命名 + 定调      生成「病名」（确诊梗）与 tone（语气基调）
          ↓
        产出：情绪转译 JSON（见 SKILL.md Step 1）
```

**三层都必须显式输出**，用户要能看见「我是怎么被理解的」。这是「懂」的证明，也是「会说话」的前提。

### 第 1 层 · 接住原话的红线

| 要 | 不要 |
|---|---|
| 原样保留用户的原词，**包括网络用语** | 翻译成书面语（「班味太重」❌ 不要改成「工作疲惫」） |
| 找出原话里的**具体细节**（谁、在哪、什么事） | 抽象成泛词（「工作」「感情」「生活」） |
| 抓住**语气信号**（标点、语气词、梗） | 忽略语气，只看字面 |

> **原词就是素材。**「被导师改崩溃了」这句话本身，比任何改写都更适合进小票。

## 三、语义意图 → 选品导向

> **这是本 Skill 与「普通点餐推荐」的分界线。** 普通推荐按营养和性价比选；本 Skill 按**这个人此刻需要食物替他做什么**来选。
> 语义意图与 `emotion-taste-map.md` 的 `taste_vector` **共同**决定选品：先按意图筛「适合的品类」，再按口味向量在品类内打分排序。

| 语义意图 | 用户此刻需要 | 选品导向（在真实菜单内） |
|---|---|---|
| **发泄型** | 想咬两口出气、要刺激 | 大块咬感 + 重口：辣味堡、大鸡排、脆薯；饮品偏冰爽 |
| **补电型** | 想被提神、想扛住 | 咖啡因 + 高热量主食：咖啡 / 拿铁 + 汉堡 + 大薯 |
| **甜慰型** | 想被哄、想被甜到 | 甜品类优先：麦旋风、派、新地、圆筒；主食选温和款 |
| **仪式型** | 想确认「今天不一样」 | 限定款 / 新品 / 完整套餐 / 招牌大单品 |
| **怀旧型** | 想回到熟悉的地方 | 经典常青款：麦香鱼、圆筒、老套餐；**不选新品** |
| **陪伴型** | 想一个人安静吃完 | 一人份完整、不要拼凑感：一份主食 + 一份小食 + 一份饮品 |
| **摆烂型** | 不想要任何决策负担 | 最常规、最容易点的单品；结构极简，2–3 件 |
| **庆祝型** | 想放大这一刻 | 大件 + 甜的 + 有存在感的组合，可以超一点点预算 |

> **冲突处理**：`语义意图` 与 `taste_vector` 主导维度冲突时，**意图优先**。
> 例：用户「被导师改崩溃」（发泄型），口味向量里 `sweet` 偏高——仍然优先重口，甜只作收尾。

## 四、病名生成规则（**护城河**）

> 视觉会被抄，病名文案不会被抄。但病名不能靠死记，要有**可生成规则**，才能覆盖长尾输入。

### 结构

```
[程度前缀] + [情绪核心] + [医学后缀]
```

| 位置 | 可选词 |
|---|---|
| **程度前缀** | 急性 / 慢性 / 突发性 / 间歇性 / 阶段性 / 晚期 / 特异性 |
| **情绪核心** | 班味 / 导师 / 论文 / ddl / 组会 / 早八 / 加班 / emo / 电量 / 周一 / 社交 / 深夜 / 食欲 / 乡愁 / 摆烂 / 上岸 |
| **医学后缀** | 综合症 / 中毒 / 反应 / 并发症 / 障碍 / 型疲惫 / 性心碎 / 应激障碍 / 过载 / 失控 |

### 生成约束

1. **必须用医学腔包装日常小事** —— 荒诞感来自「把琐事当成病」，这是确诊梗的笑点结构
2. **必须是用户自己语境里的词** —— 「被导师改崩溃」→ 病名要含「导师」，不能换成「学术压力」
3. **长度 4–8 字为佳**，小票上要放得下
4. **不能真冒犯** —— 不涉及真实疾病、身材、收入、家庭关系
5. **同一情绪簇内要能出多个病名**，避免每次都是同一个

### 生成示例（一簇多解）

以「被导师改崩溃」为例：

```
导师性精神内耗        情绪防线急性崩溃        学术性心碎
反复修改型职业倦怠    阶段性自我怀疑        灵魂返厂维修
```

> 小票上取**一个**作为「确诊」，其余可作为后续复玩时的新鲜感来源（同一情绪给不同病名）。

## 五、语气校准（「够会说话」的规格）

用户的新方向明确要求：**可保存、可分享、可自嘲**。「自嘲」是关键字——它不是「安慰」的同义词。

### 三种语气的正确打开方式

| tone | 正确 | 错误（常见翻车） |
|---|---|---|
| `gentle_comfort` | 「今天已经很努力了。／ 吃饱，明天再战。」 | 「不要难过啦，你是最棒的！」（油腻、空洞） |
| `dry_humor` | 「生活把你按在地上摩擦。／ 但薯条还是热的。」 | 「哈哈你也太惨了吧」（变成嘲讽用户） |
| `hype` | 「你熬过的夜，／ 都变成了今天的底气。」 | 「太厉害啦！你就是天选之子！」（彩虹屁） |
| `quiet_companion` | 「不说话也没关系。／ 吃完再走。」 | 「加油！明天会更好！」（鸡汤） |

### 自嘲的四个手法（小票文案可直接调用）

| 手法 | 说明 | 示例 |
|---|---|---|
| **医学腔** | 把情绪说成病，用确诊口吻 | 「确诊：慢性牛马综合症」 |
| **一本正经说废话** | 用严肃语气讲无所谓的事 | 「世界很吵。／ 但巨无霸不会。」 |
| **反常安慰** | 不安慰，反而承认现实 | 「周一不会消失，／ 但咖啡因会先到。」 |
| **把自己写成第三方** | 用旁白口吻，制造距离感 | 「这里没人认识你。」 |

### 硬约束（不可违反）

- 处方文案：**两行，每行 ≤ 14 字**
- 不卖惨、不煽情、不说教
- 不用直播话术（亲 / 宝子 / 家人们）
- 不嘲讽用户处境
- 不写机器口吻（「根据你的情绪分析」）
- 敏感话题（疾病、身材、收入、家庭）一律不碰

## 六、反例清单（不符合本 Skill 语气的写法）

| ❌ 不要写 | ✅ 应该写 | 原因 |
|---|---|---|
| 「我理解你的疲惫」 | 「今天已经很努力了。」 | 前者是客服腔，后者是朋友腔 |
| 「推荐您搭配一份营养均衡的套餐」 | 「今天就要吃点扎实的。」 | 前者是营养师，后者是同桌的人 |
| 「检测到您的情绪…」 | 「今天被什么绊住了？」 | 前者是机器，后者是人 |
| 「生活总会好起来的！」 | 「难的会过去。／ 先吃点热的。」 | 前者是口号，后者是具体动作 |

## 七、维护说明

- 本语料库**允许持续扩充**：真实使用中遇到接不住的说法，直接追加到对应簇
- 每个簇至少保持 5 条，低于 5 条时该簇覆盖不足
- 新增簇时，必须同时补 `语义意图` 与 `tone`，否则 Step 4 无法消费
- 语料库的**质量**（是否真实、是否够新）直接决定 Skill 的「懂不懂年轻人」，这是核心资产，优先于视觉迭代
